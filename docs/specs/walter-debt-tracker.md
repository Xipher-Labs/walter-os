# Walter-OS technical-debt tracker — spec

**Status**: ready for `/write-plan` after operator approval
**Issue**: #2 (`Walter-OS technical debt tracker: .walter-debt.md + walter-os debt-report CLI`)
**Target release**: v0.5.0 (alongside multi-model wizard #24)
**Depends on**: existing `walter-os justify` flow + `walter-os.toml` `protection_level` (both already in main).

## Problem

Walter-OS already has two pieces that should compose into a coherent debt-tracking story but don't:

1. **`protection_level`** in `walter-os.toml` (`experimental` → `sandbox` → `staging` → `production`) — the audit gate degrades by level so hackathons can ship fast.
2. **`walter-os justify`** — appends `{ts, pkg, version, level, reason, operator, expires}` entries to `~/.config/walter-os/justify-log.jsonl` whenever the operator deliberately bypasses a gate (unpinned dep, skipped age check, etc.).

What's missing: when the operator wants to promote a repo from `experimental` → `production`, there's no surface that says "here's the debt you must clear first". The justify log is global, not per-repo, and it's invisible to anyone other than the operator who created it.

For hackathons especially: the team that ships in 48h needs to know in week 3 (when the project goes prototype → startup) what corners got cut. The justify log alone doesn't transfer that knowledge.

## Non-goals

- A general-purpose project-management tool. This is *specifically* about debt that the audit + protection-level system already touched.
- Tracking arbitrary TODO comments in code. Not in scope — use `track-pending` skill for that.
- Cross-repo debt aggregation. v0.5.0 stays per-repo; cross-repo rollup is a Control Tower (Phase V) follow-up.
- Replacing `walter-os justify`. We surface its output, not replace it.

## Decisions (proposed)

| # | Decision | Why |
|---|---|---|
| D-1 | **`.walter-debt.md` lives at the REPO root**, committable. Gitignored by default — operator opts in to commit. | In-repo is reviewable + survives branch hops. Operators with sensitive repos can keep it private; operators sharing with a team commit it. |
| D-2 | **The JSONL log is the source of truth; `.walter-debt.md` is a derived view rendered on demand by `walter-os debt-report --write`.** `walter-os justify` appends ONLY to `~/.config/walter-os/justify-log.jsonl` and never touches `.walter-debt.md` directly. The view file is regenerated explicitly via `debt-report --write` (called automatically by `walter-os protection set` and by a post-`justify` hook for operator convenience). | Single source of truth — eliminates the D-2 vs D-3 contradiction in earlier drafts where both files could be authoritative. `.walter-debt.md` is fully overwritable from the log; an operator who deletes it gets it back on the next `debt-report --write`. |
| D-3 | **Manual `[ ]`→`[x]` toggles in `.walter-debt.md` are NOT trusted by the promotion gate (D-4).** The gate reads `justify-log.jsonl` directly. Operators CAN toggle checkboxes in the rendered view for personal-tracking purposes; the next `debt-report --write` will re-render based on the log state (auto-reconciled entries become `[x]`; unresolved entries remain `[ ]`). | Reconciles the trust boundary: the view file is editable for human convenience, the log is what the gate believes. Prevents an "I'll just edit the markdown" promotion bypass. |
| D-4 | **Promotion gate via `walter-os protection set <level>`.** Refuses to upgrade if unchecked debt exists, unless `--clear-debt "reason"` is passed. The `--clear-debt` invocation itself is logged as a justify entry. | Forces the operator to acknowledge unaddressed debt before levelling up. Mirrors the existing `walter-os.toml audit_gate` discipline. |
| D-5 | **Auto-close on reconciliation.** When a justify expires (90d TTL) OR the pinned-package check passes OR the audit clears the finding, mark the corresponding `.walter-debt.md` entry as `[x] done — auto-reconciled YYYY-MM-DD`. | The file stays useful without manual maintenance. |
| D-6 | **Daily-audit integration.** `daily-supply-chain-audit` emits an `info`-level finding for any debt entry older than N days (configurable; default 30). | Surfaces debt rot without being noisy. |
| D-7 | **Three output formats**: `md` (default, writes to `.walter-debt.md`), `json` (CI integration), `table` (terminal). | Same convention as `walter-os spend report`. |

## Acceptance criteria

### AC-1 — `.walter-debt.md` schema + auto-write
- [ ] `.walter-debt.md` is created on first `walter-os justify` invocation in any repo (cwd is the repo).
- [ ] Schema:
  ```markdown
  # <Project name from walter-os.toml> — technical debt
  
  > Auto-generated. Source: `~/.config/walter-os/justify-log.jsonl` filtered to
  > this repo. Edit `## Notes` freely; the `## Skipped or deferred` and
  > `## Promotion checklist` sections are regenerated by `walter-os debt-report`.
  
  ## Skipped or deferred
  
  - [ ] 2026-05-21 — `cool-new-mcp@latest` not pinned — hackathon launch
        - justify-id: `j-2026-05-21T03:14:22Z-abc12`
        - expires: 2026-08-19 (90 days, matching the justify TTL)
  - [x] 2026-05-12 — bats coverage for `submitClaim()` skipped — re-added 2026-05-19 (`b1f9...`)
  
  ## Promotion checklist (clear before → production)
  
  - [ ] Pin all `@latest` packages to exact versions
  - [ ] Re-run `daily-supply-chain-audit`; address findings ≥ HIGH
  - [ ] CI green on the branch
  
  ## Notes
  
  <free-form operator notes; not regenerated>
  ```
- [ ] When `.walter-debt.md` does NOT exist and `walter-os justify` runs, the file is created with frontmatter + the first entry.
- [ ] `.gitignore` is updated to add `.walter-debt.md` UNLESS the operator passes `--commit-debt` once (toggles a `commit_debt = true` field in `walter-os.toml`).

### AC-2 — `walter-os debt-report` subcommand
- [ ] `walter-os debt-report [--repo <path>] [--format md|json|table] [--write]` works.
- [ ] Default behavior with no flags: prints markdown to stdout. With `--write`: regenerates `.walter-debt.md` at the repo root.
- [ ] `--format json` emits an array of `{justify_id, ts, pkg, version, level, reason, expires, status}` records suitable for CI parsing.
- [ ] `--format table` prints a terminal-friendly ANSI table.
- [ ] Reads `~/.config/walter-os/justify-log.jsonl` and filters entries to the current repo. The existing justify-log schema does NOT carry a repo identifier today, so this AC also adds a `repo` field to the schema (populated at justify-write time by `cmd_justify` via `git rev-parse --show-toplevel || pwd`). Pre-existing entries without `repo` are matched by best-effort heuristics (cwd + commit-graph proximity) for backwards-compat, with a one-time `walter-os debt-backfill` CLI to attach `repo` to historical entries.
- [ ] Cross-references current state:
  - If the pkg is now pinned (no longer matches the `@latest` pattern that triggered the justify) → mark `[x] done`.
  - If the justify has expired (per `expires` field) → mark `[x] expired — debt is automatically void; re-justify if still needed`.
  - If the audit currently reports the same finding still active → keep `[ ]` unchecked.

### AC-3 — `walter-os protection set <level>` promotion gate
- [ ] New subcommand `walter-os protection set <experimental|sandbox|staging|production>`.
- [ ] Reads current level from `walter-os.toml`. If new level is a *promotion* (higher than current):
  - Runs `walter-os debt-report --format json` and counts unchecked items.
  - If count > 0 and `--clear-debt "reason"` was NOT passed → exits 1 with the count + a `walter-os debt-report` hint.
  - If `--clear-debt "reason"` WAS passed → logs a new justify entry with `kind: "promotion-with-debt"`. The existing `check-release-age.py` consumer doesn't recognize this kind today and would treat it as an opaque justify entry; this AC ALSO updates `check-release-age.py` to recognize `kind: "promotion-with-debt"` as a no-op (it's a promotion log, not a package-pin justification) so the daily audit doesn't misfire on it.
- [ ] Demotions (e.g., `production → experimental`) are always allowed (no debt gate needed; operator is taking a precaution).
- [ ] Updates `walter-os.toml` `protection_level` in place after the gate passes.

### AC-4 — Auto-close on reconciliation
- [ ] `walter-os debt-report --write` walks every entry in `.walter-debt.md` (Skipped or deferred section) and:
  - For pkg-pinning debt: checks if the named pkg now appears in `walter-os.toml` `pins` or `package.json` exact-version constraints → marks `[x] done — pinned`.
  - For test-coverage debt: matches `bats coverage for X` against `tests/**/*X*.bats` existence → marks `[x] done — coverage added`.
  - For TTL expiry: if `expires < now()` → marks `[x] expired — auto-reconciled`.
- [ ] Operator can manually toggle any `[ ]` to `[x]` and the next `--write` preserves their toggle (the auto-reconciler never UN-checks an item).

### AC-5 — Daily-audit reminder
- [ ] `skills/daily-supply-chain-audit/scripts/audit.sh` adds a `check_debt_age()` step that:
  - For each repo on the operator's machine (configurable via `WALTER_REPO_DIRS`) reads `.walter-debt.md`.
  - For every unchecked item with `ts` older than `WALTER_DEBT_REMINDER_DAYS` (default 30) emits an `info` finding `debt-rot-<repo>-<justify-id>`.
- [ ] No CRITICAL or HIGH escalation — debt rot is an `info` reminder, not a block. Operator clears via `walter-os debt-report --write`.

### AC-6 — Tests + docs
- [ ] `tests/walter/walter-debt.bats` covers:
  - First `justify` creates `.walter-debt.md`
  - Subsequent `justify` appends without losing operator-edited `## Notes`
  - `debt-report --format json` parses cleanly
  - Promotion to `production` with unchecked debt exits 1; with `--clear-debt "reason"` succeeds
  - Auto-reconciliation marks pinned-pkg entries `[x] done — pinned`
  - TTL expiry marks entries `[x] expired`
- [ ] `docs/operational/walter-debt-tracker.md` (new) explains the philosophy + the lifecycle diagram + CI integration recipe.
- [ ] CHANGELOG entry under `[Unreleased] → Added`.

                             │

                             │
       ┌─────────────────────┼─────────────────────┐
       │                     │                     │

## Threat model

- **Debt-bypass attack.** An attacker who can edit `.walter-debt.md` could mark all items `[x]` and trick the promotion gate. Mitigation: AC-3 reads from `justify-log.jsonl` (source of truth), NOT `.walter-debt.md`. The file is a human-readable summary; the gate doesn't trust it.
- **`walter-os.toml` tampering.** If the operator's `walter-os.toml` is in repo, an attacker who lands a malicious PR could downgrade `protection_level`. Mitigation: pre-commit hook (`hooks/branch-flow-guard.sh` extension) refuses commits that lower the level. Documented in CHANGELOG.

## Out of scope

- Cross-repo debt aggregation (Control Tower follow-up).
- Auto-suggest "what to do" for each debt entry. The `reason` field is the operator's note; we don't try to be smarter.
- Integration with external tools (Linear, Jira). Out of scope; the JSON output is enough for any team to pipe into their tracker.

## Recommended PR ordering

1. AC-1 — `justify` writes to `.walter-debt.md` (file format + schema).
2. AC-2 — `walter-os debt-report` subcommand (read + format).
3. AC-3 — `walter-os protection set` promotion gate.
4. AC-4 — auto-reconciliation logic.
5. AC-5 — daily-audit `check_debt_age()`.
6. AC-6 — tests + docs + CHANGELOG.

Each PR is ≤200 LOC, runs the 3-round review, and references this spec.

## Open questions for the operator

1. **`.walter-debt.md` location**: in-repo root (proposal) vs `.walter/debt.md` (subdir)? Default proposed: root for visibility.
2. **Gitignore default**: gitignored OR committed by default? Default proposed: gitignored, opt-in to commit (`--commit-debt` flag toggles `walter-os.toml` field).
3. **`WALTER_DEBT_REMINDER_DAYS`**: 30 is the default; reasonable? Lower (14) for tight-discipline operators? Default proposed: 30; operator-overridable.
