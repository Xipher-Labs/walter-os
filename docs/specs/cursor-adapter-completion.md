# Cursor Adapter Completion — First-Class Cursor Support

**Status**: Draft
**Owner**: architect
**Created**: 2026-05-21
**Linear/Plane**: I-04

## Problem

Cursor is the dominant AI-enabled editor for the developer market that
Walter-OS targets. As of v0.4.5-alpha, Cursor support is documented in at
least three places in the README as "manual wiring" or "backlog work":

- Line 155: "Cursor can follow the same rules once you wire its rules file
  manually."
- Lines 167-168: "Cursor can follow the same philosophy through a manual
  Cursor rules file today; a generated adapter is still backlog work."
- Lines 1679-1680: "AGENTS.md is not auto-loaded by all tools: Cursor requires
  the Cursor rules file, not AGENTS.md. A Cursor adapter is tracked in the
  backlog."

This has been the state since v0.2.0. Every release that ships without closing
this sends a signal to Cursor users that Walter-OS considers them second-class
adopters. Given that Cursor's market share among AI-enabled editors is
substantial, this gap materially limits OSS adoption.

"First-class Cursor support" means: after running `install.sh`, Cursor picks
up the Walter-OS agent contract automatically through its native configuration
mechanism, without the operator needing to manually copy, translate, or
maintain a separate rules file.

## Proposed solution

Cursor natively supports two configuration mechanisms: a repo-level
`.cursorrules` file (legacy, plain text) and a `.cursor/rules/` directory
with MDC files (current recommended format, supports multiple rule files with
metadata). Walter-OS's `install.sh` should generate a `.cursor/rules/`
directory structure in the operator's home directory (or a per-repo adapter
at the operator's request), populated from the current AGENTS.md content.

The adapter is generative: `install.sh` reads the installed AGENTS.md cascade
and produces `.cursor/rules/walter-os.mdc` as a derived artifact. When AGENTS.md
updates, running `./install.sh --upgrade` regenerates the Cursor rules. The
Cursor rules file is always a derived artifact, never the source of truth —
AGENTS.md is.

Additionally, the `tier-1.md` install prompt should be updated to explicitly
cover the Cursor adapter step. Cursor users should be able to paste `tier-1.md`
into Claude Code or Cursor itself and get first-class setup.

## Acceptance Criteria

- [AC-1] `install.sh` (or a new `install.sh --cursor` flag) generates
  `~/.cursor/rules/walter-os.mdc`. The file contains:
  - The core disciplines from the global AGENTS.md (rigor levels, branch flow,
    TDD gate, review loop, commit hygiene, PR title convention).
  - A header comment: `# Generated by walter-os install.sh — do not edit
    manually. Re-run install.sh to update.`
  - A `description` and `globs` frontmatter block compatible with Cursor's
    MDC format.
- [AC-2] When `install.sh --upgrade` is run, the existing
  `~/.cursor/rules/walter-os.mdc` is regenerated from the current AGENTS.md.
  The regeneration is idempotent.
- [AC-3] `walter-os doctor --cursor` is a new subcommand (or flag on the
  existing doctor) that:
  - Checks whether `~/.cursor/rules/walter-os.mdc` exists.
  - Checks whether the content hash of the generated file matches the hash
    that would be produced from the current AGENTS.md (i.e., detects whether
    the rules file is stale after an AGENTS.md update).
  - Returns PASS, STALE (file exists but outdated), or MISSING.
- [AC-4] `setup/agent-install/tier-1.md` includes a Cursor-specific step
  after the Claude Code / Codex CLI steps: "If you use Cursor, the Cursor
  adapter has been generated at `~/.cursor/rules/walter-os.mdc`. Verify with
  `walter-os doctor --cursor`."
- [AC-5] A bats test `tests/install/cursor-adapter.bats` verifies:
  - Running `install.sh --cursor` (in a temp directory context) produces a
    `.cursor/rules/walter-os.mdc` file.
  - The produced file contains the required header comment.
  - The produced file contains the MDC frontmatter (`description:`, `globs:`).
  - Running `install.sh --cursor` twice is idempotent (second run does not
    fail).
- [AC-6] The README's "Known limitations" section removes or updates the
  "AGENTS.md is not auto-loaded by all tools: Cursor requires the Cursor rules
  file" entry. It is replaced with: "Cursor support is provided via a generated
  `.cursor/rules/walter-os.mdc` file. Run `install.sh` (or re-run with
  `--upgrade`) to keep it current."

## Non-goals

- Generating per-repo `.cursorrules` or `.cursor/rules/` files. The adapter
  targets `~/.cursor/rules/` (user-level, applies to all Cursor projects).
  Per-repo Cursor configuration is the operator's responsibility.
- Supporting the legacy `.cursorrules` (single-file) format. MDC is the
  current Cursor standard.
- Generating MCP server configuration for Cursor. Cursor's MCP configuration
  is managed separately in Cursor settings; documenting the bridge is a
  follow-up task.
- Replacing AGENTS.md with Cursor rules as the source of truth. AGENTS.md
  remains canonical.

## Open questions

- Q1: Should the Cursor adapter be generated as part of the default
  `install.sh` run, or only with an explicit `--cursor` flag? Recommendation:
  generate by default if Cursor is detected (`command -v cursor` or
  `[ -d ~/.cursor ]`), skip with a INFO log if not detected. Operator decides.
- Q2: Should `walter-os doctor` (without flags) include the Cursor check as a
  standard item? Recommendation: yes, as a non-blocking INFO item (not a
  WARN or ERR if Cursor is not installed).
