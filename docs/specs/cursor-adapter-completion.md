# Cursor Adapter Completion — First-Class Cursor Support

**Status**: Draft
**Owner**: architect
**Created**: 2026-05-21
**Linear/Plane**: I-04

## Problem

Cursor is the dominant AI-enabled editor for the developer market that
Walter-OS targets. As of v0.4.5-alpha, Cursor support is documented in at
least three places in the README as "manual wiring" or "backlog work":

- Line 155: "Cursor can follow the same rules once you wire its rules file
  manually."
- Lines 167-168: "Cursor can follow the same philosophy through a manual
  Cursor rules file today; a generated adapter is still backlog work."
- Lines 1679-1680: "AGENTS.md is not auto-loaded by all tools: Cursor requires
  the Cursor rules file, not AGENTS.md. A Cursor adapter is tracked in the
  backlog."

This has been the state since v0.2.0. Every release that ships without closing
this sends a signal to Cursor users that Walter-OS considers them second-class
adopters. Given that Cursor's market share among AI-enabled editors is
substantial, this gap materially limits OSS adoption.

"First-class Cursor support" means: after running `install.sh`, Cursor picks
up the Walter-OS agent contract automatically through its native configuration
mechanism, without the operator needing to manually copy, translate, or
maintain a separate rules file.

## Proposed solution

**Codex R1 correction (2026-05-21):** the initial draft proposed generating
`~/.cursor/rules/walter-os.mdc` as a user-level adapter, but Cursor's actual
model is different from what that assumed:
- `.cursor/rules/*.mdc` files are **project-scoped** (live inside each repo,
  not in `~/.cursor/`). User-level rules live in Cursor's Settings UI as
  plain text.
- Cursor now **natively reads `AGENTS.md`** as a supported rules source
  (recently added; documented at `https://docs.cursor.com/context/rules`).
  For operators on a current Cursor version, no adapter is strictly required.

Revised solution:

1. **Per-repo MDC adapter (opt-in convenience)**: `./install.sh --cursor-rules`
   run from the repo root reads the project's AGENTS.md cascade and emits
   `.cursor/rules/walter-os.mdc` IN THE PROJECT (not in `~`). Useful for
   operators who want the rules visible in their IDE's rule list or want
   compatibility with Cursor versions that pre-date the AGENTS.md support.
2. **User-level Cursor preferences**: print a recommended plain-text block
   to the operator + instruct them to paste it into Cursor Settings → Rules.
   We do NOT generate a file under `~/.cursor/` because Cursor doesn't read
   from there.
3. **Native AGENTS.md path**: the docs explicitly state Cursor reads
   AGENTS.md natively. For most Cursor users on a recent version, the
   adapter is unnecessary — the AGENTS.md cascade Walter-OS already installs
   is loaded by Cursor without any extra step. The `--cursor-rules` flag
   becomes a "materialize for visibility" convenience, not a hard requirement.

The adapter remains generative when used: `install.sh --cursor-rules` reads
the project's AGENTS.md cascade and produces `.cursor/rules/walter-os.mdc`
as a derived artifact. AGENTS.md is always the source of truth.

Additionally, the `tier-1.md` install prompt should be updated to explicitly
cover the Cursor adapter step. Cursor users should be able to paste `tier-1.md`
into Claude Code or Cursor itself and get first-class setup.

## Acceptance Criteria

- [AC-1] `install.sh --cursor-rules` (new flag) generates
  `<repo-root>/.cursor/rules/walter-os.mdc` IN THE PROJECT being installed
  into (NOT in `~/.cursor/` — Cursor doesn't read from there). The file
  contains:
  - The core disciplines from the global AGENTS.md (rigor levels, branch flow,
    TDD gate, review loop, commit hygiene, PR title convention).
  - A header comment: `# Generated by walter-os install.sh --cursor-rules —
    do not edit manually. Re-run to update.`
  - A `description` and `globs` frontmatter block compatible with Cursor's
    MDC format.
- [AC-2] When `install.sh --upgrade --cursor-rules` is run, the existing
  project-local `.cursor/rules/walter-os.mdc` is regenerated from the
  current AGENTS.md. The regeneration is idempotent.
- [AC-3] `walter-os doctor --cursor` is a new subcommand (or flag on the
  existing doctor) that:
  - Checks whether the current Cursor version reads `AGENTS.md` natively
    (prints an info line if yes — adapter is optional in that case).
  - If `.cursor/rules/walter-os.mdc` exists in the current repo, checks
    whether its content hash matches what `--cursor-rules` would generate
    from the current AGENTS.md (detects stale rules files).
  - Returns PASS, STALE (file exists but outdated), or NOT_GENERATED
    (no file; either the operator didn't opt in or Cursor reads AGENTS.md
    natively — both fine).
- [AC-4] `setup/agent-install/tier-1.md` includes a Cursor-specific section
  after the Claude Code / Codex CLI steps. Two sub-paths:
  - "Recent Cursor (with native AGENTS.md support): no extra step. Cursor
    reads the Walter-OS AGENTS.md cascade automatically. Verify with
    `walter-os doctor --cursor`."
  - "Pre-AGENTS.md-support Cursor OR you want the rules visible in the
    Cursor rules panel: run `./install.sh --cursor-rules` from the repo
    root."
- [AC-5] A bats test `tests/install/cursor-adapter.bats` verifies:
  - Running `install.sh --cursor-rules` (in a temp directory context that
    looks like a repo) produces a project-local `.cursor/rules/walter-os.mdc`
    file at the repo root, NOT at `~/.cursor/rules/`.
  - The produced file contains the required header comment.
  - The produced file contains the MDC frontmatter (`description:`, `globs:`).
  - Running `install.sh --cursor` twice is idempotent (second run does not
    fail).
- [AC-6] The README's "Known limitations" section removes or updates the
  "AGENTS.md is not auto-loaded by all tools: Cursor requires the Cursor rules
  file" entry. It is replaced with: "Cursor support is provided via a generated
  `.cursor/rules/walter-os.mdc` file. Run `install.sh` (or re-run with
  `--upgrade`) to keep it current."

## Non-goals

- Generating a user-level Cursor rules file under `~/.cursor/`. Cursor does
  not read disk-based rules from `~/.cursor/`; user-level preferences live
  in Cursor Settings → Rules for AI and must be pasted manually. The install
  script prints a recommended block but does NOT write to `~/`.
- Supporting the legacy `.cursorrules` (single-file) format. MDC is the
  current Cursor standard.
- Generating MCP server configuration for Cursor. Cursor's MCP configuration
  is managed separately in Cursor settings; documenting the bridge is a
  follow-up task.
- Replacing AGENTS.md with Cursor rules as the source of truth. AGENTS.md
  remains canonical; the MDC file is a derived artifact.
- Auto-generating the project-local `.cursor/rules/walter-os.mdc` on every
  install. The `--cursor-rules` flag is opt-in because (a) Cursor reads
  AGENTS.md natively on recent versions, and (b) project-local file creation
  inside the operator's repo should be an explicit choice.

## Open questions

- Q1: ~~Should the Cursor adapter be generated as part of the default
  `install.sh` run, or only with an explicit `--cursor` flag?~~
  **Resolved (Codex R1, 2026-05-21)**: opt-in only, via `--cursor-rules`.
  Rationale: (a) project-local file creation inside the operator's repo
  must be explicit; (b) Cursor reads AGENTS.md natively on recent versions,
  so no adapter is required for most users.
- Q2: Should `walter-os doctor` (without flags) include the Cursor check as a
  standard item? Recommendation: yes, as a non-blocking INFO item. NOT_GENERATED
  is INFO (Cursor uses AGENTS.md natively, or the operator hasn't opted in);
  STALE is WARN; PASS is silent unless `--cursor` is passed.
- Q3: How does the adapter behave in a monorepo with multiple AGENTS.md files
  (cascade across `~/work/`, `~/Projects-Personal/`, repo root)? Recommendation:
  generation reads the effective cascade for the current `$PWD`, same way the
  install script resolves AGENTS.md for the agent contract today. Deferred to
  the implementation issue once the cascade-resolution helper is extracted.
