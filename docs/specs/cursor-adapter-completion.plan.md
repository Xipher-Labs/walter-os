# Implementation Plan: cursor-adapter-completion

Executes against `docs/specs/cursor-adapter-completion.md`.

**Codex R1 correction (2026-05-21):** earlier draft of this plan assumed
`~/.cursor/rules/walter-os.mdc` (user-scope) and unconditional generation.
Cursor's MDC rules are **project-scoped** (live inside each repo) and Cursor
now reads `AGENTS.md` **natively**, so the adapter is opt-in convenience
(materializes for IDE visibility / supports pre-AGENTS.md-aware Cursor
versions). Flag is `--cursor-rules`. Target path is
`<repo-root>/.cursor/rules/walter-os.mdc`, NOT `~/.cursor/`.

## Task 2: Write the Cursor MDC generation function in install.sh [AC-1, AC-2]

- File: `install.sh` (modify)
- Change: Add a `generate_cursor_adapter()` function that:
  1. Resolves the project root (the directory containing the AGENTS.md
     cascade — usually `$REPO_ROOT` / `$PWD` of the install run). It is an
     error to call this without a repo context.
  2. Creates `<repo-root>/.cursor/rules/` directory if it does not exist.
  3. Generates `<repo-root>/.cursor/rules/walter-os.mdc` by extracting the
     core discipline sections from the installed AGENTS.md cascade (rigor
     levels, branch flow, TDD gate, review loop, commit hygiene, PR title
     convention).
  4. Prepends MDC frontmatter:
     ```
     ---
     description: Walter-OS agent discipline contract
     globs: ["**/*"]
     alwaysApply: true
     ---
     ```
     (`alwaysApply: true` is the Cursor MDC field for "load for every
     conversation in this project". Verify exact field name against current
     Cursor MDC docs at https://docs.cursor.com/context/rules.)
  5. Prepends the required header comment immediately after the frontmatter:
     `<!-- Generated by walter-os install.sh --cursor-rules — do not edit
     manually. Re-run to update. -->`
  6. Records the AGENTS.md content hash in a trailing HTML comment for
     staleness detection: `<!-- agents-md-sha256: <hash> -->`.
- Wire the function into the main install flow:
  - Only called when `--cursor-rules` is explicitly passed. Do NOT auto-generate
    even if `command -v cursor` succeeds — Cursor reads AGENTS.md natively now,
    so unsolicited project-local file creation would be surprising.
  - If `--cursor-rules` is passed but no AGENTS.md exists at repo root: error
    out with a clear message ("no AGENTS.md found — Cursor adapter needs the
    cascade to be installed first").
- Verify: `bats tests/install/cursor-adapter.bats` passes all four tests (GREEN).

## Task 3: Add `doctor --cursor` subcommand [AC-3]

- File: `bin/walter-os` (modify)
- Change: In `cmd_doctor()`, handle `--cursor` flag. The check has three
  independent signals:
  1. **Native AGENTS.md support**: Detect if Cursor is installed
     (`command -v cursor`) and, if possible, print the Cursor version. Print
     an INFO line: `"Cursor reads AGENTS.md natively in v0.42+. Adapter is
     optional."` (Do not gate on version detection — Cursor's CLI may not
     expose version reliably; the INFO line is informative, not a check.)
  2. **Project-local adapter presence**: Check for `./.cursor/rules/walter-os.mdc`
     in the current repo. Three possible states:
     - `NOT_GENERATED` — file absent. INFO (not warning): "no adapter found;
       Cursor uses AGENTS.md natively, or run `./install.sh --cursor-rules`
       to materialize."
     - `PASS` — file exists and the recorded `agents-md-sha256` matches the
       hash of the current AGENTS.md cascade.
     - `STALE` — file exists but hash differs. WARN: "adapter is stale; run
       `./install.sh --cursor-rules` to regenerate."
- Also wire `--cursor` as a non-blocking INFO check in the default
  `walter-os doctor` output (no flag needed for basic presence check).
- Verify: in three temp repo setups, `bin/walter-os doctor --cursor` returns
  the correct status for each (NOT_GENERATED, PASS, STALE — simulate STALE by
  manually editing the file after generation).
