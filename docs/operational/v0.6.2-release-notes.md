# Walter-OS v0.6.2 Release Notes

**Date**: 2026-06-09
**Status**: Alpha patch release

v0.6.2 is a release-tag reconciliation patch. The published `v0.6.1` tag stays
immutable as the 2026-06-07 release; this patch documents the post-tag merge
batch now on `main` so operators can pin a clean follow-up release instead of
depending on a moved tag.

## Highlights

- Headscale diagnostics: this command reports common `/machine/register`
  runtime blockers, including stopped containers, missing Docker access, and
  the known Tailscale/Headscale capability-version drift signature.

  ```bash
  setup/walter-host/services/headscale/deploy.sh --diagnose
  ```
- Headscale routing: the Tailscale control-plane hostname is routed outside the
  Cloudflare Tunnel path, while admin access remains behind the gated route.
- Cloudflare CI routing: Cloudflare-specific tests now live in the service CI
  slice, reducing unrelated hook-suite churn.
- Local previews: `walter-os preview local` gives operators a deterministic
  local preview adapter while the broader per-PR preview provider work remains
  open.
- Release hygiene: the changelog and README now point at `v0.6.2` rather than
  implying that the already-published `v0.6.1` tag should be retconned.

## Upgrade

Preview first:

```bash
walter-os upgrade --dry-run
```

Upgrade the local install:

```bash
walter-os upgrade --target v0.6.2
```

For a Walter-VM host, keep service rollouts explicit:

```bash
walter-os upgrade --all --snapshot --yes
walter-os upgrade --all --service headscale
```

Do not restart or migrate every Docker service automatically. Name each service
that should roll forward.

## Verification

Before cutting the final GitHub release, run:

```bash
walter-os release doctor --target v0.6.2
```

The doctor should pass before the `v0.6.2` tag is created. If the tag already
exists, stop and reconcile release artifacts before moving forward.
