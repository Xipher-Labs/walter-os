## Tag + release sequence

Once the pre-tag checklist is complete:

```bash
git checkout main
git pull origin main --ff-only

# 1. Tag (must be from a feature branch — branch-flow-guard refuses
#    pushes while on main):
git checkout -b chore/push-v0.4.0-tag
git tag -a v0.4.0 -m "v0.4.0 — audit P1 closure, founder-skills bundle, OpenRouter, workflow consolidation"
git push origin refs/tags/v0.4.0
git checkout main
git branch -D chore/push-v0.4.0-tag

# 2. release.yml fires automatically on the tag push:
#    - validate tag matches VERSION
#    - generate changelog via git-cliff
#    - create GitHub Release
#    - generate SBOM + checksums + cosign signature
#    - upload to release

# 3. Verify both jobs succeeded:
gh run list --workflow=release.yml --limit 3 --json status,conclusion,headBranch
# Expect: latest run with headBranch=v0.4.0, status=completed, conclusion=success

# 4. Confirm artifacts:
gh release view v0.4.0 --json assets -q '.assets[].name'
# Expect: walter-os-v0.4.0.sbom.cdx.json, checksums.sha256,
#         checksums.sha256.sig, checksums.sha256.cosign.bundle
```

## If the release-security job fails

If `release.yml` succeeds but the `security` job inside it fails (cosign issue, SBOM generation issue, etc.):

```bash
# Re-run only the security portion via workflow_dispatch
gh workflow run release.yml --ref main -f tag=v0.4.0

# This triggers the consolidated workflow with the existing release
# already in place; the `release` job will detect-and-skip the create
# step (idempotent — see PR #62), and the `security` job re-runs.
```

## Post-tag operator actions

1. **Publish release notes**: GitHub Release is auto-created. Operator can edit the body to add a personal note + link to the migration guide.
2. **Announce**: tweet / LinkedIn / Telegram bot — content-writer skill drafts the launch announcement.
3. **Re-baseline external hooks**: any operator-side `walter-os baseline-external-hooks` if their checkout includes the bumped submodule pin.
4. **Update operator overlays** if `WALTER_ENV_ALLOWLIST` extension or `WALTER_PROFILE` defaults changed.

## Rollback plan

If a P0 surfaces in v0.4.0 within 24h of release:

1. **Don't yank the tag.** Leave v0.4.0 in place; tag yanks confuse operators who pinned.
2. Cut **v0.4.1** with the fix on top of v0.4.0.
3. If the v0.4.0 issue is severe enough to recommend "don't upgrade":
   - Edit the GitHub Release body to mark v0.4.0 as "withdrawn — upgrade to v0.4.1 directly"
   - Operator-facing comms (Telegram bot / Twitter) explain.
