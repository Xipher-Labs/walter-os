# Verifying release artifacts

Each Walter-OS release is signed with [cosign](https://github.com/sigstore/cosign)
using keyless OIDC signing (no long-lived private key). The signing identity is
tied to the GitHub Actions OIDC token and is auditable via the
[Rekor](https://github.com/sigstore/rekor) transparency log.

Three artifacts are attached to every release from v0.4.1 onward:
- `walter-os-<tag>.sbom.cdx.json` — CycloneDX SBOM generated by syft
- `checksums.sha256` — SHA-256 checksums over the full release payload
- `checksums.sha256.cosign.bundle` — cosign transparency log bundle (a
  single file carrying signature + Fulcio certificate + Rekor entry).
  This is the **only** first-class verification target.

Cosign v3+ forces bundle-only output; raw `.sig` + `.pem` companion files
are deprecated upstream and no longer produced. Releases v0.3.0 and v0.4.0
shipped a standalone `.sig` from older cosign versions but never the matching
keyless certificate, so that standalone `.sig` was never actually verifiable
on its own — the `.cosign.bundle` (which carries the cert embedded) was
already the only verification path for those releases. v0.4.1 makes that
explicit by dropping the dead `.sig`.

## Verification steps

```bash
# Download the release assets
gh release download <tag> \
  --pattern "checksums.sha256*" \
  --pattern "walter-os-<tag>.sbom.cdx.json"

# Verify the checksum file signature via the bundle.
cosign verify-blob \
  --bundle checksums.sha256.cosign.bundle \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp 'https://github\.com/Xipher-Labs/walter-os/\.github/workflows/release\.yml.*' \
  checksums.sha256

# Verify every artifact named in checksums.sha256 (SBOM, archives, etc.)
sha256sum --check checksums.sha256
```

Replace `<tag>` with the target release tag (e.g., `v0.4.1`).

## Note on workflow file name and org/repo slug

`--certificate-identity-regexp` must reference the workflow that signed the
release. From **v0.3.1 onward**, signing happens in `release.yml` (the SBOM +
cosign steps were folded in from the standalone `release-security.yml`). Older
bundles produced by `release-security.yml` remain verifiable — replace the
regexp tail with `release-security\.yml.*` when checking pre-v0.3.1 releases.

The repository slug is **`Xipher-Labs/walter-os`** (mixed case). Bundles
produced before the org migration to Xipher Labs use a different slug —
release notes for those older versions print the exact identity to use.

## Installing cosign

```bash
# macOS
brew install cosign

# Linux (via Go)
go install github.com/sigstore/cosign/v2/cmd/cosign@latest

# Or use the sigstore/cosign-installer GitHub Action in CI
```
