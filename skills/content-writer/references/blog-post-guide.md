# Blog Post Guide

Structural reference for the `content-writer` blog post mode.

## Headline Formulas

- **How-to**: "How to [achieve outcome] without [common obstacle]"
- **Number list**: "[N] Ways to [verb] [result] (Even If [objection])"
- **Counterintuitive**: "Why [conventional wisdom] Is Wrong About [topic]"
- **Question**: "Why Do [target audience] [unexpected behavior]?"
- **Specific result**: "How We [achieved result] in [timeframe] Using [method]"

**Anti-patterns:**
- Vague titles: "Thoughts on Developer Tooling" — tells the reader nothing.
- Clickbait that doesn't deliver: headline promises X, post delivers Y.
- All-caps for emphasis: unnecessary and off-brand.

## Structure

```
TL;DR: [40 words or fewer — what the reader will learn]

# [H1 Title]

[Hook — one provocative sentence]
[Problem — 2-3 sentences establishing stakes]
[Promise — one sentence: "By the end of this post, you'll know X"]

## [H2: Section 1 — Context / Why this matters]
[3-5 paragraphs]

## [H2: Section 2 — Core insight or method]
[3-5 paragraphs]

## [H2: Section 3 — Practical application]
[3-5 paragraphs with examples or code]

## [H2: Section 4 (optional) — Common mistakes / anti-patterns]
[2-3 paragraphs]

## [H2: Conclusion]
[Synthesize the key point; do not introduce new information]
[CTA: one action — subscribe / try the product / read related post]
```

## Anti-Patterns

- Wall-of-text paragraphs: break at 3–4 sentences.
- No examples: abstract claims without concrete illustration lose readers.
- Buried lede: the main insight should be in the first 150 words.
- Weak CTA: "I hope this was useful" is not a CTA.
- Keyword stuffing: once the keyword appears naturally, stop forcing it.
